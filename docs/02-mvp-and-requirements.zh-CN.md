# MVP 需求与验收标准

[English](02-mvp-and-requirements.md) | 简体中文

本文只定义**首版产品必须完成的事情**，不维护某一首 Demo 的内容或技术实现细节。功能稳定编号和成熟度仅见[功能库](PRODUCT_FUNCTIONS.zh-CN.md)；真正进展只看[状态](STATUS.zh-CN.md)。

## P0 — 完整可运行的主路径

1. **接入既有曲库：** 索引用户授权的本地目录，读取合法取得的完整录音。不要求重新开发 NAS 存储与备份基础设施。
2. **元数据门槛：** 读取音乐人、曲名及可获得的发行、录音、版本身份；真正无法识别时明确报错。缺少封面、年份或可选声学数据，不应单独导致失败。
3. **区分具体录音：** 单独维护 Work / Recording / Release / PlayableSource 及署名；不能仅因曲名相同就合并不同版本。
4. **Music Context Pack：** 整合具有来源的元数据、音乐知识、用户曲库可播放性和**可选的整曲声学特征**；标记不确定性和缺失项。
5. **音乐关系检索：** **优先从用户自己的曲库**召回候选，使用明确的作品关系，具备权限时可辅以声音相似性；为每个关系保留可解释理由和证据。
6. **节目策划：** 在写口播之前确定主题、选曲、串场方向、时长预算以及各曲目的可播放来源。
7. **模型 Provider 抽象：** 文本 LLM **本地/云端均可明确配置**，有统一接口；不得静默转云端或上传私人音乐文件。即使首个 Demo 只实际接入一家供应商，也必须测试配置和失败行为。
8. **自然口播与 BGM：** 用可替换的 TTS Provider 生成原创主持语音，搭配合法背景音乐和 Ducking；商业歌曲仍按独立的授权播放项执行。
9. **电台播放器：** 按真实文件时长执行口播/歌曲时间轴，支持播放、暂停、跳过和下一首推荐理由。
10. **明确错误：** 元数据无法确认、曲目不能播放、来源受限、模型失败时不得编造成功结果。

## P1 — 私人音乐体验深化

- 验证 Lenovo Smart Storage **真实存在且有授权的文件、身份、权限及播放接口**；能力满足后再开发对应适配器。
- 可按需集成现成音乐服务器，不为了 AI Radio 重造完整存储服务。
- 后台索引、人工修正元数据、跨设备播放及安全远程访问。
- 根据用户许可的收藏、歌单和历史收听信息建立个人音乐画像。
- 对合法可分析的本地文件增加速度、音色、和声、Embedding 等更完整的声学特征。
- 逐步支持超出本地曲库的新音乐发现，但必须明确来源与授权情况。
- 节目保存、选择其他策展主题、重新选曲和局部重新生成。
- 至少验证一种本地 LLM 和一种云端 LLM 的真实端到端效果，比较质量、延迟、资源和隐私边界。

## 首版明确不做

- 歌曲内部的任意时刻识别、乐谱对齐或片段提取。
- 无可用身份信息时的音频指纹自动补全。
- 自建完整 NAS、备份、文件共享、多用户系统。
- 假定 Spotify、Apple Music、网易云等 DRM 音频可以抓取、抽取和未经许可混音。
- 将“情绪标签”或相似度得分直接当作创作影响关系。
- 未经验证就声称完全离线、零成本或本地模型与云端效果相同。

## 主路径验收

给定用户授权曲库中一首**可识别、可播放的完整录音**：

1. 展示明确的录音身份与来源。
2. 从用户曲库提供至少两首**真实可播放**的关联录音，附有据可查或明确标为主观声学解释的推荐理由。
3. 先生成可检查的选曲和节目方案，再生成自然主持语音。
4. 结合独立的主持音轨/BGM 和完整歌曲播放，随实际时长调整节目。
5. 对必要元数据缺失、歌曲失效给出可理解的错误状态。

验收须覆盖**节目策划质量、元数据准确性、音乐关系证据、实际听感、隐私/配置行为、真实播放**。尚未锁定具体模型及硬件。
