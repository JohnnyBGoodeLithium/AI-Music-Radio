# 已确定决策与待研究问题

[English](05-open-questions.md) | 简体中文

**讨论基线 · 2026-11-18**

## 已确定的产品决策

- 本地私人音乐服务器是**基础能力**，合法拥有的音乐文件不依赖持续流媒体订阅也能播放。
- 三个 Persona 为 **Music Owner、Music Explorer、Deep Listener**，对应收藏拥有、音乐探索和深度聆听。
- 每次输入是**一个可识别的完整录音/文件**，可以是更大型作品的一章。
- 必要元数据是前置条件；身份无法确认可以报错。v0 不强制音频指纹恢复或文件内部段落识别。
- 重点选择有可靠材料、值得进行音乐解读的作品，不以覆盖所有短视频神曲为目标。
- **新版 Demo 001 种子：** 1992 年 Bob Dylan **录音生涯 30 周年**纪念音乐会的现场合唱版《My Back Pages》，不是 20 周年。
- 第一条探索路径：**现场合作演唱 → Dylan 1964 年原版 → The Byrds 1967 年版本**，后续可沿参演音乐人继续探索。
- 主持人口播和原创/授权 BGM 与歌曲播放保持逻辑分离，制作和播放受实际版权许可限制。
- 核心产品说明、MVP、Demo、架构、决策文档及 README 均采用**英文/简体中文配套更新**；规范见 `AGENTS.md`。
- 尚未选定或实现具体应用技术栈、模型和服务器方案。

## 待决策的产品问题

1. MVP 应从本地文件夹索引开始，还是先接入现成的自托管音乐服务器？
2. 首个播放器是 Web、桌面客户端，还是家庭网络的多设备播放器？
3. 允许生成节目前，最低的音乐身份与事实证据门槛是什么？
4. 推荐如何平衡**同一作品的不同录音**与不同音乐人的关联作品？
5. 当用户本地缺少被推荐曲目时，是替换、外链提示还是引导补齐？
6. 哪些行为必须断网可用，哪些可由用户显式选择云模型服务？

## 待研究的工程问题

1. 适合复用的开源音乐服务器及其播放接口是什么？
2. Music Context Pack 如何持久化 Work/Recording/Release 身份和证据引用？
3. 多人合唱署名与不同版本之间的关系怎样可靠校验？
4. 哪种中文 TTS 能自然读出六位英文音乐人的姓名？
5. 可用于实际演示的合法音乐文件和背景音乐来源是什么？
6. 实际录音时长、授权范围、响度以及目标硬件预算如何确定？

## 近期执行步骤

1. 确认 1992 年现场版、1964 年原版及 The Byrds 1967 年版的合法音乐文件。
2. 校验最小元数据，搭建稳定可查询的测试曲库。
3. 制作第一份有事实依据、可审阅的节目策划方案。
4. 生成原创中文主持语音、授权/原创 BGM，接入时间轴播放器。
5. 试听、核对事实和音乐关系之后，再扩展更多音乐人关联路径。

## 仍然存在的限制

目前还没有实测音频来源及授权、用户文件时长、TTS 模型、流媒体 SDK 或真实音乐服务器。不能把规划中的能力描述成已经实现。
